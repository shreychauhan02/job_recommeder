2. WHY IT KEPT BREAKING (root cause, now confirmed)
----------------------------------------------------
- extract_skill.py hard-requires spaCy 2.x's model format for PhraseMatcher skill
  extraction. Modern spaCy 3.x models are structurally incompatible (config.cfg
  format didn't exist in 2.x). This is not fixable without pinning old spaCy.
- resparser.py also depends on `tika`, which needs a local Java runtime running
  in the background (Apache Tika server) — another fragile moving part.
- job.py re-scrapes a live Indeed job link at runtime via BeautifulSoup — will
  break instantly since site HTML has changed since 2022.
- Conclusion: skill-extraction + live-scraping layers are unsalvageable without
  a full legacy environment. We drop both.

4. NEW BUILD PLAN (Streamlit + FastAPI, current library versions)
--------------------------------------------------------------------
Data:
  - Load indeed_data.csv as-is (title, company, salary, description, link)
  - Clean/dedupe descriptions once at startup, cache result

Resume input:
  - User uploads PDF resume in Streamlit
  - Extract text using pdfplumber or PyPDF2 (NOT tika — no Java dependency)

Matching engine (backend/main.py, FastAPI):
  - POST /match endpoint: takes resume text -> returns top-N ranked jobs
  - TF-IDF vectorizer fit ONCE on all job descriptions + the resume together
    (fixes the old code's per-row re-vectorization slowness)
  - Cosine similarity -> match % per job
  - Sort, return top 10-20

Frontend (app/app.py, Streamlit):
  - Upload resume PDF
  - Call FastAPI /match endpoint
  - Display ranked job table: Title | Company | Match % | Link
  - Optional: bar chart of top matches (matplotlib, same as your other projects)

Deployment / polish:
  - requirements.txt with no unnecessary pins
  - .env for any secrets (none strictly needed here, no API keys required)
  - README with clear run steps (pip install -> uvicorn -> streamlit run)
